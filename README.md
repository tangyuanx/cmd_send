# 命令定向 · Cmd Send

Windows / macOS 桌面工具：编辑 UTF-8 TXT，将光标所在命令或所选有效内容发送到明确绑定的其他应用输入区。三栏布局、浅色/深色主题、真实置顶、逐字符发送、暂停/继续/停止、持续循环。不会建立 SSH 或串口连接。

窗口采用统一的无边框界面：顶部空白区域可拖动，右上角提供最小化、最大化/还原和关闭按钮。关闭前检查未保存修改，并停止剩余发送任务。Windows 不显示系统菜单栏；打开文件、保存和关闭窗口分别支持 Ctrl+O、Ctrl+S、Ctrl+W，Mac 对应使用 ⌘。

程序、安装器和快捷方式采用与主界面左上角一致的终端图标：深灰圆角底、白色「>_」符号。

## 运行

- Mac：解压 macOS arm64 包，打开 `Cmd Send.app`。适用于 Apple Silicon。首次打开后，在「系统设置 → 隐私与安全性 → 辅助功能」添加并允许该应用，再退出并重新打开。可以在工具的「选择目标」说明中打开这个设置页；授权需本人完成。
- Windows：下载 `cmd-send-版本号-Windows-x64-Setup.exe`，按向导选择安装目录，使用「命令定向」快捷方式启动。只需下载这一个 EXE；安装后不要单独移动程序文件。旧 ZIP 版用户先退出旧版，再安装新版。
- 两个平台的包均包含 `快速验证.txt`。打开顶部文件名菜单，选择「打开 TXT 文件…」。长按「选择目标」约 400ms，保持按住移到其他软件的实际输入区，松开绑定。
- 默认每条发送后按 Enter。首次建议在空白文本框中测试；在设置中关闭 Enter 可只输入文字。
- 点击发送：无选区时发送当前行完整命令，成功投递后推进到下一条；选区按顺序发送，保留首尾部分、空格与引号。标题、空行、整行注释自动过滤。
- 「发送」始终只发送一轮，未选中内容时发送后移到下一条有效命令。「重复发送」遵循设置中的「指定次数 / 持续循环」，重复当前命令或选区，结束后保留原光标与选区。按钮下方显示间隔和停止条件；设置中的轮数指整组选中命令的发送轮数。间隔指命令之间的等待，不是字符速度。
- Ctrl+S / Mac ⌘S 保存到原文件；Ctrl+Enter / ⌘Enter 发送；Ctrl+F / ⌘F 查找；工具拥有焦点时 Esc 取消拾取或停止发送。快捷键不全局注册。
- 查找时全部匹配项持续高亮，当前项有绿色边框和整行提示；点击上一处/下一处或按 Shift+Enter/Enter 可循环导航，并定位长命令中屏幕外的结果。搜索栏不会覆盖正文；Esc 关闭查找。
- 发送只表示完成输入投递，不代表目标软件已成功执行命令。

界面中文优先使用黑体（Windows SimHei），英文与数字优先使用 Times New Roman。界面正文 15px、辅助信息 13px、命令正文 16px；未安装对应字体时使用系统回退字体。

## 软件更新

点击顶部版本号，手动从 GitHub 检查最新稳定版本。Windows 安装版发现更新后，点击「下载更新」查看进度；通过 SHA-512 校验后，点击「安装并重启」覆盖原安装目录并自动重启。升级会停止发送，检查未保存的 TXT 修改，可保存、放弃修改或取消升级。普通退出不会自动安装已下载的更新，启动时也不会自动检查或下载。网络与校验失败可以重试，期间可继续使用当前版本。

重启后会重新打开上次的 TXT 与活动文件，并保留发送设置和主题。重新选择发送目标后再发送；文件被移动或删除会提示重新打开，不会自动恢复发送任务。TXT 只在明确保存时写入。macOS 和开发环境可手动检查版本并打开 GitHub 发布页面下载，当前不提供原地升级。

Windows 发布附件中的 `latest.yml`、`.blockmap` 是升级元数据，普通用户只需下载 Setup.exe。GitHub 的下载速度取决于网络连接。

## 目标策略与边界

Mac 使用系统辅助功能识别具体文本输入控件，检查进程、窗口、输入区和焦点，向绑定进程投递 Unicode 键盘事件。需要时短暂激活输入区，投递后尽量恢复此前应用。无可识别输入区会拒绝绑定。

Windows 使用 Win32 识别实际窗口/子控件，保存进程启动时间、线程、窗口类并验证句柄。标准 Edit / RichEdit（含 WinForms 文本框）使用后台 WM_CHAR；明确识别出的 MobaXterm MoTTY / PuTTY 终端也通过其原生 WM_CHAR 接口后台投递文字和回车，不要求抢占焦点或模拟点击。MobaXterm 名称从宿主窗口识别，绑定仍指向具体终端，并校验终端与宿主的身份和父子关系。其他控件优先通过系统 UI Automation 聚焦。终端或自绘控件不提供文本接口时，保存所选区域在窗口内的位置，发送前激活目标并短暂点击该位置以恢复焦点，随后逐字符校验焦点并使用 SendInput。鼠标位置会尽量恢复，窗口移动后仍按窗口内的位置定位；切换终端页签、拆分面板或调整输入区布局后请重新绑定。只读控件、按钮等非输入区域仍拒绝绑定。控件识别使用 Windows 自带的 PowerShell 独立进程，不更改系统执行策略。失败时停止，不自动重试、不转投当前窗口。

没有使用剪贴板。系统权限、管理员窗口、自绘控件及不同终端的兼容性需要真实验证。首版只有 UTF-8；保留 BOM 和原换行格式。不自动保存，不显示执行日志或输出预览。

## 开发与构建

```sh
npm ci
npm test
npm start
npm run build:mac
npm run build:win
```

图标源文件为 `assets/icon.svg`。需要重新生成时，安装 `CairoSVG==2.9.1`、`Pillow==12.3.0` 后运行 `python scripts/generate-icons.py`；正常构建直接使用仓库内的 PNG、ICO 和 ICNS。构建会检查实际应用图标资源，Windows 安装升级验证还会检查安装后的程序及卸载器。

Node.js 22+；Mac 上可交叉打包 Windows x64。产物位于 `artifacts/`。macOS 包为本地 ad-hoc 签名，未使用 Developer ID、未公证；Windows 安装包未代码签名。Windows 测试包含真实自绘输入控件的绑定、中文/emoji/回车、焦点改变后停止与标准文本框投递；具体终端软件的兼容性仍需实机验证。`npm run test:mobax` 在 Windows 上下载官方 MobaXterm Home Edition 26.5 临时测试包（固定 SHA-256），实际验证终端收到中文、emoji、回车，另一应用保持焦点且不收到文字，关闭目标后停止投递；不会将 MobaXterm 打入发行包。Windows 上构建完成后可执行 `npm run test:update`，验证真实安装、手动检查、下载校验、原地升级、自动重启与文件/设置恢复。测试使用隔离安装目录和本机更新源，不发布测试版本。

推送 `main` 且项目版本号变化时，GitHub Actions 在双平台测试、构建、真实 MobaXterm 兼容性验证和 Windows 安装升级验证成功后创建对应 Tag，发布 Windows EXE 安装包、升级元数据、macOS ZIP、源码包和 SHA-256 校验文件。直接推送版本 Tag 的发布流程也保留。

`npm run test:search` 在真实 Electron 渲染器中验证搜索高亮、导航、双向滚动、主题、编辑保存和发送请求，截图保存在 `test-output/search/`。该测试不向其他应用注入输入。

源码仅使用 Electron 隔离的预加载接口；文件身份与写入、目标注册及冻结的发送队列均在主进程。停止、关闭应用取消剩余任务，修改文件退出时要求保存/丢弃/取消。
