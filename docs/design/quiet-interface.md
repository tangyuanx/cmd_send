# 命令定向界面改版 · 2026-10-28

基于主分支 `47948c9`（v0.1.21）。保留 Electron、原生 HTML/CSS、目标绑定与发送队列。设计方向是微对比中性色阶、克制的绿色功能强调与稳定的三栏工作区；布局差异 3/10，动效强度 3/10，信息密度 5/10。

## 改动

- 合并叠加的样式覆盖，统一字体、间距、圆角与主题令牌。
- 相邻背景使用约 1%–3% 明度差；保留终端标识。界面使用系统无衬线字体，命令使用等宽字体。
- 深色主题的普通、中等、强调字重统一减少 40。
- 编辑器增加保存和查找入口，显示保存状态、场景数量与有效指令总数。
- 右侧待发送内容调用与实际发送一致的 `sendPlan`，保留选区片段和原始字符，不解析 HTML。
- 输入框以双层阴影反馈聚焦；数字使用等宽数字；行内图标偏移 -0.125em；段落使用 pretty 换行。
- 定时投递设置通过 Grid 的 0fr/1fr 过渡展开；折叠内容设为 inert，校验失败时自动展开。
- 成功提示在 2.5 秒后淡出；图标反馈使用短暂回弹；系统减少动态效果设置会禁用这些动画。
- 命令编辑保持即时、稳定，不对用户输入施加逐字延迟。

## 验证

- Node 回归测试：87 项通过，4 项 Windows/macOS 原生平台检查在 Linux 跳过。
- 真实 Chromium 渲染：发送预览与载荷、完成后的光标推进、选区带入定时任务、查找高亮、折叠与隐藏控件校验、主题切换、最小窗口、减少动态效果、反馈自熄、空状态和准确保存全部通过。
- 检查 1280×820、1040×760、680×440、390×720 的布局，确认无横向溢出。
- 校验独立 HTML 预览：主题切换、模拟绑定、模拟发送及光标推进可用。
- Windows/macOS 真实窗口拖动和原生输入投递未在本环境复测；本次未修改其实现。

运行 `npm run test:ui` 生成测试证据；运行 `npm run preview:ui` 生成独立交互预览。预览接口仅模拟发送与文件操作，不被正式桌面应用加载。
